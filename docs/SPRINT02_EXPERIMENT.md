# SPRINT 02 — Протокол эксперимента

Документ фиксирует, **что** мы меряли, **на чём** и **в каком порядке**, до того как были
получены цифры тестового периода. Всё, что подбиралось, подбиралось на dev-периоде и затем
было заморожено в `evaluation/frozen_config.json`.

---

## 1. Научные правила, которые соблюдались

| Правило из брифа | Как оно обеспечено технически (а не «честным словом») |
|---|---|
| Пороги фитятся на train/dev и замораживаются | Драйвер `experiments/sprint02.py` имеет три стадии: `--stage dev` → `--stage freeze` → `--stage test`. Стадия `test` **отказывается стартовать** без `evaluation/frozen_config.json` (`_load_frozen()` кидает `SystemExit`), и ничего не подбирает. |
| Нельзя менять метки, увидев результат | Правило разметки менялось **один раз**, до любого прогона модели по корпусу, по результатам `experiments/label_prevalence.py` на dev; обоснование и таблица распространённости — в `docs/SPRINT02_RECON.md`. Множитель 3× **не** ослаблялся. |
| Нельзя удалять «плохие» примеры | Единственные отсевы — `no_data` и `low_baseline`, оба считаются **до** разметки и только по окну наблюдения (`meta.eligibility.computed_from == "observation window only"`), тест `test_low_traffic_entities_are_dropped_using_observation_data_only`. |
| Нельзя использовать будущее | Три непересекающихся окна S → O → L, ряд признаков обрезается на `observation_end`. Тесты: `tests/test_realworld.py`, `tests/test_regression_sprint02.py` (день алармa не меняется при обрезании будущего; промпт не содержит ни одного пост-решенческого значения). |
| Нельзя менять промпт ради одной модели | Один `build_prompt()` на все арки и обе модели; отключённое свидетельство **удаляется из промпта**, а не заменяется заглушкой. Тест `test_every_arm_uses_the_shared_prompt_builder`. |
| Нельзя черри-пикать | Полная сетка детекторов (95 точек) сохранена целиком в `evaluation/gate_ablation.json → detector_tuning.grid`; выбран максимум по PR-AUC на dev, а не лучший на тесте. |
| K не предполагается равным 10 | `precision_at_k_curve` считает K ∈ {5,10,15,20,25,30,40,50}; `choose_operating_point` берёт **наибольший** K, у которого Precision@K ≥ product-floor 0.50. |

## 2. Стадии

```
stage dev      → сетка детекторов × горизонт решения, затем 5 арок аблации
stage freeze   → запись evaluation/frozen_config.json (детектор, H, арка, K)
stage test     → однократный прогон тестового периода с замороженным конфигом
```

Команды (воспроизводимо):

```bash
PYTHONPATH=src python3 experiments/sprint02.py --stage dev
PYTHONPATH=src python3 experiments/sprint02.py --stage freeze
PYTHONPATH=src python3 experiments/sprint02.py --stage test --subsample 40 --extra-arms llm_full
PYTHONPATH=src python3 experiments/benchmark_models.py --n 12
```

## 4. Аблация свидетельств (dev, 329 топиков, 143 алармa, 143 вызова модели на арку)

Арки отличаются **только** полем `GateFeatures`; промпт-билдер, декодинг и корпус общие.

| Арка | Что видит гейт | P | R | FPR | PR-AUC | P@10 | Lead |
|---|---|---|---|---|---|---|---|
| `stats_only` | — (контроль: детектор без гейта) | 0.084 | 0.706 | 0.420 | **0.180** | 0.200 | 10.42 |
| `heuristic` | детерминированная проверка устойчивости (контроль без LLM) | 0.128 | 0.588 | 0.218 | **0.188** | 0.200 | 10.03 |
| `llm_series_only` | ряд + аларм | 0.067 | 0.118 | 0.090 | 0.062 | 0.000 | 5.57 |
| `llm_context_only` | контекст + аларм | 0.000 | 0.000 | 0.000 | 0.177 | 0.200 | n/a |
| `llm_full` | всё (конфигурация Sprint 01) | 0.000 | 0.000 | 0.000 | 0.123 | 0.100 | n/a |

Bootstrap-интервалы (1000 ресэмплов по топикам) лежат в `arms[<arm>]["ci"]`; для
`llm_series_only` 95% CI по recall = [0.000, 0.300], то есть арка статистически неотличима
от нуля.

**Два наблюдения, которые определяют весь спринт:**

1. На реальных данных Qwen3-0.6B **не фильтрует, а глушит**: две из трёх LLM-арок
   отклоняют *все* 143 алармa (TP=FP=0). Это не «высокая точность», это отказ работать.
2. `heuristic` — детерминированные 15 строк без нейросети — на dev **не хуже**
   любой LLM-арки по PR-AUC. Именно ради этого контроля арка и была добавлена: без неё
   выигрыш гейта был бы неинтерпретируем.

### 4.1. Вырожденные арки и выбор замороженной

Первый прогон выбрал `llm_context_only` (PR-AUC 0.177) — арку, которая не пропускает
ни одного аларма. Так вышло потому, что ранжирование при пустом множестве предсказаний
откатывается на статистику детектора, и PR-AUC «арки» оказывается PR-AUC детектора.
Это ошибка процедуры отбора, а не результат, поэтому в драйвер добавлен фильтр:

```python
alive = {a: d for a, d in llm_arms.items() if d["metrics"]["recall"] > 0}
```

Кандидатов осталось ровно один — `llm_series_only`, он и заморожен. Отброшенные арки
записаны в конфиг явно (`arm_selection.degenerate_arms`), чтобы отбор был аудируемым.

## 5. Рабочая точка (K)

| K | Precision@K | Recall@K |
|---|---|---|
| 5 | 0.000 | 0.000 |
| 10 | 0.000 | 0.000 |
| 15 | 0.067 | 0.059 |
| **20** | **0.100** | **0.118** |
| 25 | 0.080 | 0.118 |
| 30 | 0.067 | 0.118 |
| 40 | 0.075 | 0.177 |
| 50 | 0.060 | 0.177 |

Product-floor precision = 0.50 (зафиксирован до прогона). **Ни один K его не проходит.**
Правило `choose_operating_point` в этом случае возвращает K с максимальным Precision@K
и явную причину `"no K clears the precision floor"`. Заморожено K=20 вместе с этой
причиной — это честнее, чем подобрать floor под данные.

Отдельно: K=10 **не** оказался лучшим ни на одной арке — на `stats_only` и `heuristic`
лучший K=5 (0.400), на замороженной арке K=20. Предположение из брифа проверено и
опровергнуто на данных.

## 6. Стоимость и кеш

Все вердикты детерминированы (`temperature=0, top_p=1, seed=42, think=false`), поэтому
вердикт кешируется по sha256(model + think + options + system + prompt) —
это мемоизация, а не приближение (тест `test_verdict_cache_key_covers_model_and_prompt`).
Без кеша пятиарочная аблация на CPU-хосте была бы неисполнима: 5 × 143 × ~5.4 с ≈ 64 минуты
только на dev.
